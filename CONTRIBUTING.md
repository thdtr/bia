# Contributing to BIA

Thanks for your interest! BIA tries to stay small, so the most useful contributions
are fixes and improvements to what's already there. New features are welcome too, but
please talk about them in an issue first.

Issues and pull requests in Portuguese are fine as well.

## Before you write code

* For a bug, open an issue with the steps to reproduce it, your OS and the output of
  `bia --version`.
* For a feature, open an issue first, and check
  [what's out of scope](docs/ARCHITECTURE.md#out-of-scope). Anything that needs the
  network won't be accepted ([docs/SEALED.md](docs/SEALED.md)).
* Themes, grammars and translations are a good way to start. See below.

## Development

```sh
git clone https://github.com/thdtr/bia && cd bia
cargo run -p bia -- .            # run BIA on its own repository
cargo test --workspace           # all tests, including the no-network check
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all
cargo deny check                 # needs `cargo install cargo-deny`
```

Use `BIA_CONFIG_DIR=/tmp/bia-dev cargo run -p bia` to develop against a throwaway
config folder.

### Where things are

* `crates/bia-core`: everything that isn't drawing. If something can be tested
  without a window, it probably belongs here.
* `crates/bia/src/app.rs`: the app state and the update loop.
* `crates/bia/src/tabs.rs`, `buffer.rs`: open files and their text.
* `crates/bia/src/ui/`: what's on screen. All colors are decided in `style.rs`.
* `assets/`: themes, translations, fonts and icons.

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) has the full map.

## Pull requests

* One topic per pull request. Small ones get reviewed faster.
* `cargo fmt`, `cargo clippy -- -D warnings` and the tests need to pass. CI runs them
  on Linux, macOS and Windows.
* Add unit tests for new logic.
* Text shown to users goes in both `assets/locales/en.json` and
  `assets/locales/pt-BR.json`. A test fails if one of them is missing a key.
* Add a line to `CHANGELOG.md` under *Unreleased*.
* If you add a dependency, say why in the pull request. We try to keep the list
  short.

## Adding a translation

1. Copy `assets/locales/en.json` to `assets/locales/<code>.json` and translate the
   values. Keep `{placeholders}` as they are.
2. Add a variant to `Lang` in `crates/bia-core/src/i18n.rs` (`ALL`, `code`, `source`,
   `from_tag`).
3. Run `cargo test -p bia-core`. It fails if a key or placeholder is missing.

## Adding a file icon

Icons are generated by a script:

1. For a language, add its two letters to `TILES` in `tools/make_icons.py`. For a new
   kind of file, add a symbol to `SYMBOLS` (16×16, artwork inside the central 10 px,
   1.2 px round strokes).
2. Run it: `python3 -m venv .venv && .venv/bin/pip install fonttools && .venv/bin/python tools/make_icons.py`.
3. Add the file to the `icons!` list and map its extension in `crates/bia/src/icons.rs`.
   The tests check that every mapped icon exists.

## Changing the logo or app icon

The files in `assets/icons/` and `assets/logo.svg` come from `tools/make_logo.py`, so
edit the script instead of the files and run it again (it needs `fonttools` and
ImageMagick 7):

```sh
.venv/bin/python tools/make_logo.py
```

## Commit messages

Write the subject in the imperative (`Fix undo after paste over selection`) and keep it
short. If the reason for the change isn't obvious, explain it in the body.
